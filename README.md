# Smart Build-Cache Invalidation System

## 1. Project Overview

The Smart Build-Cache Invalidation System is a Python-based software build automation project that detects changes in source files and avoids unnecessary recompilation.

It uses SHA-256 hashing to determine whether source files have changed and reuses previously compiled outputs when possible.

## 2. Problem Statement

Traditional build processes may repeatedly compile unchanged files, wasting time and computing resources.

This project implements file-level cache invalidation to rebuild only modified files while reusing valid cached results.

## 3. Objectives

- Automate Python source file compilation.
- Detect source file modifications using SHA-256.
- Store and retrieve build-cache metadata.
- Identify cache hits and cache misses.
- Rebuild modified files automatically.
- Skip unnecessary compilation.
- Display build execution results.

## 6. Implementation Steps

### Step 1: Project Setup

Created the project directory and organized the source code, sample files, and cache storage into separate folders.

### Step 2: Virtual Environment

Created and activated a Python virtual environment to isolate the development environment.

### Step 3: Sample Project Creation

Created two Python files, `file1.py` and `file2.py`, to demonstrate the build automation process.

### Step 4: SHA-256 Hashing

Implemented a hashing function to generate a unique content fingerprint for each source file.

### Step 5: Cache Management

Implemented a JSON-based cache to store previously calculated file hashes.

### Step 6: Automated Build

Used Python's `py_compile` module to compile source files and save the generated bytecode files.

### Step 7: Cache Hit Detection

If a file's hash matches its cached hash and its compiled output exists, the system skips recompilation.

### Step 8: Cache Invalidation

When a source file changes, its SHA-256 hash changes, causing the system to compile that file again and update its cached hash.

### Step 9: Execution and Verification

Executed the application multiple times to verify first-time compilation, cache reuse, and selective rebuilding.
